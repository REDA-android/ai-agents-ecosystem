## 2023-11-20 - [Command Injection via direct execution endpoint]
**Vulnerability:** The API endpoint `/api/code/execute` allowed clients to directly submit and execute arbitrary Python code natively on the host using `subprocess.run([sys.executable, temp_path])` without running the input string through the established `SafetyGuardrail` validations. This is an OS command injection / Sandbox Escape vulnerability where critical actions like `os.system("rm -rf /")` could have been executed bypassing intended human approval policies.
**Learning:** Even when input code is not technically an OS command out-of-the-box, giving unrestricted arbitrary code execution capability implicitly allows spawning underlying shell access that bypasses higher-level command validators.
**Prevention:** All un-sandboxed code execution pipelines must route the incoming source code payload itself through the `SafetyGuardrail.evaluate_command` system using `SafetyPolicy.HUMAN_APPROVAL` prior to persisting it to disk and executing it.
