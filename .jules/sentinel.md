## 2025-02-14 - Validate Code Execution Endpoints with Guardrails
**Vulnerability:** The backend endpoint `/api/code/execute` implemented code execution via `subprocess.run` accepting arbitrary Python code from the user, lacking any form of safety validations. This constitutes a Critical Risk of Command Execution, where a user might pass malicious strings evaluating to catastrophic OS operations. Passing Python source code to a shell command evaluation function (like `SafetyGuardrail`) is ineffective because it can't detect obfuscated python code execution.
**Learning:** In a heavily AI-driven workspace dealing with autonomous agents executing terminal scripts or commands on the host environment, a standard shell-based guardrail isn't enough for direct python evaluation endpoints. A Python AST (Abstract Syntax Tree) static analyzer must be implemented to check for dangerous imports (like `os`, `sys`, `subprocess`) or dangerous builtins (`eval`, `exec`) before calling `subprocess.run(python_executable, script)`. In addition, simple `ast.Name` checking is not enough, malicious actors can easily bypass it by using python object attribute access (`module.function()`), accessing `__builtins__`, or using `getattr` to indirectly retrieve dangerous functions. A robust AST walker must examine `ast.Attribute` to block dynamic calls to forbidden functions.
**Prevention:** Every direct invocation of `subprocess` acting as a REPL must implement deep AST-based static validation acting as a restricted python sandbox, explicitly blocking modules like `os` and `subprocess`, and robustly analyzing `ast.Attribute` and `ast.Name` nodes to prevent function access bypassing via attributes (`getattr`, `__builtins__`, etc.).
